## Что это за проект

Сайт-портфолио и приём заказов: главная, очередь заказов, портфолио,
калькулятор стоимости, Twitch-долги, T.O.S. Админка встроена в сам сайт
(вход по Supabase Auth, карандашик → режим редактирования).

- **Прод:** https://milariart.ru (Amvera, регион msk1, SSL Let's Encrypt)
- **Репозиторий:** github.com/suurinf/milaria-next (публичный — не коммить бэкапы и ключи)
- **База:** Supabase (бесплатный тариф, лимит egress 5 ГБ/мес)

## Архитектура — читать обязательно

Сайт это **ОДИН файл `index.html`** (~520 КБ), который отдаёт самодельный
Node-сервер `server.js` без единой зависимости во время работы.

Внутри `index.html`:
- HTML-оболочка (мета-теги, домен, canonical, OG, CDN-скрипты)
- один большой `<style>` — вся CSS
- **7 блоков** `<script type="text/babel">` — JSX-код приложения
- **2 обычных** `<script>` — `data.js` и `supabase-client.js`
- CDN: React 18.3.1, ReactDOM, supabase-js **2.119.0** (версия закреплена)

Это **не Next.js и не React-проект со сборкой.** Старый Next.js-каркас удалён
8 ноября 2026. `amvera.yml` запускает `node server.js`.

### Сборка

Исходники лежат в `src/`, из них собирается `index.html`.
На этой машине Windows: **`python`, не `python3`** (`python3` — заглушка Store).

```bash
python scripts/build.py
```

Скрипт берёт **текущий `index.html` как основу** (поэтому правки в HTML-оболочке
переживают пересборку) и заменяет в нём CSS, 7 babel-блоков и 2 обычных скрипта.

**Порядок babel-блоков важен** и зашит в скрипт:
`components, home, queue, portfolio, calculator, sections-misc, app`

Если число блоков в `index.html` не совпадает со списком — сборка остановится.

## Деплой

1. `git push` в `main`
2. GitHub шлёт вебхук на `webhook.git.msk1.amvera.ru/github/3670`, Amvera пересобирает
3. Проверить `https://milariart.ru/debug`:
   - `Сборка: <sha1-8> · <KB> · <дата>` — отпечаток `index.html`
   - `JSX: скомпилирован на сервере ✓` — babel отработал
   - живой лог `CACHE` / `SUPA_ERR` / `PROXY` / `STORAGE`

Правки только в `server.js` отпечаток не меняют — проверяй по поведению
(например, `/server.js` должен отдавать 404).

**Если push не пересобрал сайт** — смотри доставку вебхука:
```bash
gh api repos/suurinf/milaria-next/hooks
```
`last_response` покажет ошибку. В ноябре 2026 старый регион msk0 неделю был
недоступен из-за ТСПУ (`502 failed to connect to host`), проект переехал в msk1.
Кнопка «Пересобрать» в Amvera собирает то, что Amvera уже получила, а не свежий GitHub.

## Supabase

URL: `https://vgwdudjgvkmlnnfgonbk.supabase.co`
Anon-ключ в коде — так и задумано, данные защищает RLS.

**Таблицы:** `queue_items`, `portfolio_categories`, `portfolio_images`,
`prices`, `calc_options`, `debts`, `links`, `settings`
(`prices` осталась в базе и в бэкапах, но сайт её не читает: раздел «Прайс» удалён)

**Bucket:** `portfolio` (публичный на чтение, запись только authenticated).
Папки: `full/`, `thumb/` — портфолио; `banner/` — слайды баннера; `site/` — значок.

### Картинки — только в Storage, не в базу

Все загрузки в админке (`ImageUploader`, портфолио) кладут файл в Storage,
в базу пишется только ссылка `/supa/storage/...`. Раньше баннер и значок
сохранялись в `settings` строками base64 (~1,5 МБ) и уходили каждому посетителю
внутри страницы. Для переноса старых есть кнопка в админке
«⇪ Картинки в хранилище» — она видна, только пока такие картинки остались.

### Трафик к Supabase идёт через прокси

У владельца провайдер с DPI — прямые обращения к `*.supabase.co` из браузера
блокируются. Поэтому данные и файлы идут через `/supa/*`, а `server.js` проксирует дальше.
**Никогда не меняй это на прямые запросы к Supabase** — сайт перестанет работать
у части посетителей в РФ.

- `/supa/rest/*` → `proxySupabase()` — данные (ответ сжимается gzip)
- `/supa/storage/*` → `proxyStorage()` — файлы, **потоком** (см. ниже)

Подмена адресов — в `PATCH` из `server.js` (перехват `fetch` для `/rest/` и `/storage/`).
**Не проксируются:** вход в админку (`/auth/`) и realtime (websocket) — они ходят
напрямую и у части посетителей падают по таймауту (`ERR_CONNECTION_TIMED_OUT` в консоли).
Сайт от этого не ломается: данные всё равно приходят через прокси.

## Грабли, на которые уже наступали

### 1. Колонки в базе (самая частая ошибка)

Ошибка `Could not find the 'X' column of 'Y' in the schema cache` означает:
в редактор добавили поле, а колонку в базе создать забыли.

**Перед добавлением любого поля в редактор — добавь колонку SQL** (Supabase → SQL Editor):
```sql
ALTER TABLE <таблица> ADD COLUMN IF NOT EXISTS <колонка> <тип>;
NOTIFY pgrst, 'reload schema';   -- без этого PostgREST не увидит колонку сразу
```
Готового SQL-файла со всеми колонками в репозитории нет.

### 2. `settings` не имеет `sort_order`

`supaFetch(table, orderBy)` по умолчанию сортирует по `sort_order`, но у
`settings` схема `key/value jsonb`. Вызывать только как `supaFetch('settings', null)`.
Иначе 400 и вечное `settings=0` в логе — из-за этого однажды молча не работала
вся серверная вставка (Метрика, favicon).

### 3. `supaFetch` возвращает `null` при сбое, `[]` только если таблица пуста

Это принципиально: раньше сбой отдавал `[]`, и упавшее обновление **затирало
хороший кэш нулями**. Сейчас в `refreshCache()` есть ретраи с нарастающей паузой
(2с/5с/15с/45с) — контейнер стартует раньше своей сети, первый заход почти всегда
ловит ECONNRESET. Не «упрощай» эту логику.

Плановое обновление кэша — раз в час; любая запись через прокси обновляет его сразу.

### 4. Storage-прокси должен быть потоковым

Был `Buffer.concat` — видео целиком ложилось в память контейнера и рвалось на
~10 МБ. Сейчас `req.pipe(pr)` / `ps.pipe(res)`.
**Обязательно пробрасывать заголовок `Range`** — без него iOS Safari вообще
отказывается играть видео.

### 5. Кириллица в ответах прокси

Склеивать ответ строкой (`body += chunk`) нельзя: буква на границе кусков
превращается в `�`. Только `chunks.push(c)` → `Buffer.concat(chunks)`.

### 6. Проверка JSX

`python scripts/check.py` — баланс скобок, `node --check` для обычного JS и
**настоящий разбор JSX тем же Babel**, что на сервере (нужен `npm install`).
Подсчёт скобок, например, не видит перенос строки внутри `'...'` — Babel видит.

### 7. Юникод в JSX-разметке

`→` внутри JS-строки превращается в `→`, а в голой JSX-разметке
(`<span>→</span>`) остаётся текстом. Писать символ напрямую.

## Что сделано и работает (не ломать)

- **HTML:** ETag + `Cache-Control: no-cache` (иначе правки не доезжали до телефонов),
  gzip (~1,5 МБ вместо ~2,4 МБ), страница собирается один раз на версию кэша
- **Наружу отдаётся только `assets/`** — `server.js`, `.git`, бэкапы и прочее дают 404
- **Серверная предкомпиляция JSX** (`precompileJSX`) — babel-standalone 2.9 МБ
  не грузится в браузер. Есть обязательный фолбэк: нет babel → отдаём как есть
- **Бэкапы:** `.github/workflows/backup.yml` раз в сутки выгружает все 8 таблиц
  в `backups/*.json` **ветки `backups`** (не main — иначе Amvera пересобирала бы
  сайт после каждого бэкапа). История бэкапов до 11.11.2026 — в истории main.
  При полном сбое выходит с кодом 1, чтобы **не закоммитить пустышку поверх
  нормальных данных**. Покрывает только базу, не Storage.
  Ручные бэкапы `milaria-backup-*.json` и папка `backups/` в `.gitignore`
- **Яндекс.Метрика** вставляется сервером, только если в `settings.metrika_id`
  задан номер. Номер санитизируется (`\D` → '')
- **SEO:** `SITE_ORIGIN` в server.js управляет robots.txt, sitemap.xml, OG
- **Иконки соцсетей:** 18 платформ, автоопределение по домену ссылки,
  `fill="currentColor"` на `<svg>` чтобы наследовать цвет темы
- **Очередь:** приоритеты (высокий/средний/низкий), сортировка приоритет →
  ближайший дедлайн, подпись «осталось N дней» со склонениями
- **Оформление** (шрифты, акцент, скругление) — константа `TWEAK_DEFAULTS` в `app.jsx`.
  Панель Tweaks и кнопка «залить демо-данные» удалены

## Безопасность — проверено, не трогать без причины

RLS включена на всех 8 таблицах и на `storage.objects`.
Правила записи выданы роли `public`, **но с условием
`auth.role() = 'authenticated'`** — это безопасно, несмотря на вид.
Файлы: чтение всем, запись/удаление только authenticated.

## Правила работы с этим проектом

1. **Правь `src/`, а не `index.html`** — иначе следующая сборка затрёт.
   Исключение: HTML-оболочка (мета-теги, CDN-скрипты), она живёт в `index.html`.
2. После правки: `python scripts/build.py && python scripts/check.py`
3. Проверяй локально: `node server.js`, затем открыть `localhost:3000` и пройти разделы.
4. Коммить осмысленными шагами — есть git, откат бесплатный.
5. Не добавляй зависимостей в рантайм сервера. `@babel/core` и `@babel/preset-react`
   нужны только для предкомпиляции и имеют фолбэк.
